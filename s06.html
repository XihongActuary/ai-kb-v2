组织与分工：谁来干，要几个人

决策会必问的一句：「这事儿谁负责？」本页给一张分工表。 说明一句：人月数是行业经验的量级估计，不是本库算出来的， 各公司差异很大，请按实际情况调整。

本页目录
五个角色一条线 每个角色干什么 要多大投入 最容易卡住的地方
本页要做的三件事

谁来做？精算 / 数据 / 核保 / IT / 合规各干什么，要多大投入，最容易卡在哪。

目标
把「谁来做」讲清楚：每个角色干什么、什么时候进场、大概要多少投入。
输出
一张角色流水线图 + 一张分工表 + 一张投入量级估计表。
怎么读
所有「人月」都是量级估计，标注为待填的必须由公司自己定。
读完你会知道
牵头人应该是精算，因为他要拍板「什么叫对」——那是立场，不是技术。

五个角色一条线

这不是五个部门各干各的，是一条链：上游定错了，下游全白干。

每个角色干什么

角色干什么什么时候进场投入量级备注
精算定义「什么叫对」：好司机线定在哪、成功标准是什么、口径怎么算全程牵头这一条做错了，后面全错——它是立场，不是技术
数据 / IT（数据侧）把核保 / 理赔 / 渠道的数据拼成一张表，保证口径一致第 1 段起重通常是最被低估的一项
核保做真相判定：逐件复核、记录依据、签字放行第 1 段起最重复核的人月 = 整本账的成本大头（见 s03）
IT（系统侧）规则引擎接模型分、落日志、留审计痕迹第 3–4 段中别小看「留痕」，审计会查
合规 / 风控准入审查、公平性审查、设定红线第 3 段起中强监管行业不能后置，否则返工
内部审计独立验证、年度审计上线后轻但必需第三道防线，不参与开发
模型开发（精算或数据兼）建模、外推体检、业务账第 3 段中本库流程可直接复用，能省一大块

要多大投入

事项量级说明本库值
数据治理1–3 人月视数据分散程度，差异极大待填
模型开发1–2 人月复用本库流程可显著压缩本库已跑通
人工复核4,400 件 × 单件耗时成本大头待填（见 s03）
系统改造1–2 人月只算接口与留痕，不含新建系统待填
验证与审计0.5–1 人月 + 年度首年一次性，之后年度经常性待填
上线后运营0.3–0.5 人月 / 年监控看板 + 季度复训待填

最小的启动配置：一个能拍板口径的精算（0.5 人力）+ 一个能拼表的数据（0.5 人力） + 一批愿意做复核的核保员（按件计）+ 一个懂接口的 IT（0.3 人力）。 第一年其实不需要专职的算法工程师——本库的流程已经把建模部分标准化了。

最容易卡住的地方

  • 口径没人拍板：好司机线到底定在承保人群中位数的多少？ 这个数三个人能吵两周。所以 s07 里把它写成「立场声明」——必须先由业务负责人签字。
  • 数据拼不出来：核保表和理赔表的主键对不上、渠道字段有多个版本。 这是最常见的延期原因，也是最该在第一段就试一试的。
  • 复核没人做：核保员本来就在满负荷，突然加 4,400 件复核。 这一条必须先算进人力计划，否则项目会静悄悄死在第二段。
  • 合规后置：到要上线了才问合规，发现模型台账、留痕、独立验证全没做，返工。
看完这一页，你只需要记住三句话
  1. 牵头人应该是精算，因为他要拍板「什么叫对」——那是立场不是技术，做错了后面全错。
  2. 第一年不需要专职算法工程师：最小配置是 0.5 精算 + 0.5 数据 + 一批复核人力 + 0.3 IT。
  3. 最容易死的地方不是建模，是复核没人做——4,400 件的人力必须先算进计划。
本页词语解释正文里带虚线的词，点一下也能到这里
训练集拿来「教」机器的那部分数据，答案一起给它看。
审计样本从被拒的人里抽一小部分，人工去查他们真实风险是多少。昂贵但能救命。
错杀真实风险明明够低，却被规则拒掉的人。本案例一共 2,259 个。
核保与承保核保 = 判断这个人能不能保、按什么条件保；承保 = 最终接下这笔业务。被拒掉的人从此就没有数据了。
上线与部署把训练好的模型接进真实业务流程，让它开始给真实的人打分。这之后的每一个错误都要付真金白银。
轮次 / 一批 / 一次更新Epoch = 全部数据完整过一遍；Batch = 一次更新拿出的那一小批；Iteration = 更新一次。
