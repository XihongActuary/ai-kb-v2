遇到问题，到底该选哪类模型

选模型的第一步不是挑算法，是定义任务。 同样一份客户表，你想「猜他今年赔多少钱」和想「判断他会不会跑掉」， 是两个完全不同的问题，要用两套完全不同的模型和两套完全不同的指标。

决策路径：三个问题定死一条路

看图，从上往下问自己三句话，答案就出来了：

  • 第 1 问（图顶部）：「我到底想算出个什么东西出来？」
    想不出来 → 说明你可能还没定义清楚业务问题，这时候写代码就是浪费时间。
    想得出来 → 进第 2 问。
  • 第 2 问（右上）：「那个东西，是一个数字，还是一类标签？」
    数字（赔多少钱、出几次险、什么时候来）→ 回归；
    标签（会/不会、是/不是、A 类/B 类）→ 分类。
  • 第 3 问（左下）：「我手上压根没有已知答案，只是想分个堆？」
    想自动分组 → 聚类（无监督）；
    要在环境里反复试错求最优 → 强化学习。

四个常见场景，对号入座

编号业务问题 要输出什么落在哪一支学习类型
1预测一套房子值多少钱一个具体价格回归监督学习
2这个客户会不会流失会 / 不会分类监督学习
3把这一万个人自动分群没有现成标签，自己分组聚类无监督学习
4让智能体学会最优动作反复试错，追求奖励最大强化学习另起一支

注意第 3 行和第 2 行的区别：「会不会流失」是有历史答案的（去年留下来的人，今年到底留没留）， 所以能做分类；「自动分群」你连「群」该叫什么名字都不知道，只能让机器按相似度高不高自己抱堆。

本案例走的是哪条路

决策问题本案例的答案为什么这么答
有明确目标结果吗？有「这批被拒的人，真实风险有多高」——一个明确的、可计算的量
结果是数字还是类别？数字 → 回归要预测的是纯保费（continuous），拆成出险次数 + 案均损失两块
有标签吗？只有一部分人有11,200 个已承保的人有真实出险记录，8,800 个拒保的一个都没有——这才是本案例真正的难点
考核指标是什么？AUC / 圈选纯度落地动作是「排序 + 圈人」，不是定价，所以不看准确率，看排序能力
本案例最容易答错的一题： 有人会脱口而出「这是二分类——好司机 / 坏司机」。 不是。「好 / 坏」只是我们最后圈完之后贴的标签（圈出来的叫疑似好司机）， 模型从头到尾学的都是纯保费这个连续数字。把「业务上的圈选决定」和「模型要预测的量」混为一谈， 是初学阶段最常见的分类错误。

判断口诀（背这一句就够）

想预测多少 → 回归；判断属于哪类 → 分类；没有标签先分组 → 聚类；连续试错求最优 → 强化学习。

把这四句和 B11 的四分区图放一起看：左边那两支（回归 / 分类）是有监督的，右边（聚类 / 强化）是无监督或另起一脉的。 判断顺序永远是先看「要预测什么」，不是先看「哪个算法名字熟」。

看完这一页，你只需要记住三句话
  1. 选模型的第一步不是挑算法，是定义任务——先回答「我要预测什么」。
  2. 数字→回归，类别→分类，无标签→聚类，试错求奖励→强化学习；本案例走的是回归这一支。
  3. 「业务上圈不圈」和「模型预测什么」是两件事，别把它们混成一个分类问题。
本页词语解释正文里带虚线的词，点一下也能到这里
监督学习每个例子都带着「标准答案」，机器照着答案学。我们这个案例全是这一类。
无监督学习没有标准答案，机器只负责把「长得像的」归成一堆。
RL不告诉它对错，只给它「加分/扣分」，让它在反复试错里自己摸索出最优做法。
回归（预测连续值）要预测的结果是一个数字（保额、收入、温度），模型学的是「输入 → 数字」这条映射。
分类（预测类别）要预测的结果是几个固定选项里的一个（会不会续保、是不是欺诈），模型学的是「打勾」。
外推（训练域外）给模型一个它训练时从没见过的类型的人打分。它可能装作很懂，其实是在瞎猜。
